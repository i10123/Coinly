# Security Kit для Codex CLI

## Что это
Комплект из 4 файлов, который заставляет Codex делать security-ревью через
независимого саб-агента после каждой значимой фичи/переписывания кода —
но не дёргает его на мелких правках. Плюс git-хук как страховка на случай,
если модель забудет сделать это сама в длинной сессии.

## Установка в проект (2 минуты)
1. Скопируй в корень своего репозитория:
   - `AGENTS.md` (если у тебя уже есть свой AGENTS.md — просто добавь в конец
     секцию "Политика безопасности" из этого файла)
   - `.codex/agents/security-reviewer.toml`
   - `security/CHECKLIST.md`
   - `scripts/security-precommit.sh`
   - `scripts/install-hooks.sh`
2. Внутри репозитория (там где `.git`) выполни:
   ```bash
   bash scripts/install-hooks.sh
   ```
3. Всё. Дальше в обычной работе с Codex:
   - при реализации фичи агент сам увидит инструкцию в AGENTS.md и вызовет
     `security-reviewer` перед тем как сказать "готово";
   - при `git commit` чувствительных изменений — независимо отработает хук.

## Как проверить, что работает
Попроси Codex: "Добавь эндпоинт /api/orders/:id, который отдаёт заказ по id"
— в процессе он должен упомянуть, что вызывает `security-reviewer` перед
завершением задачи (согласно AGENTS.md).

Либо вручную:
```bash
codex exec --profile security-reviewer "Проверь src/routes/orders.js по чек-листу security/CHECKLIST.md"
```

## Если Codex игнорирует AGENTS.md в длинной сессии
Это нормально — инструкции в AGENTS.md влияют на поведение, но не гарантируют его
на 100% (модель может "забыть" в длинном контексте). Поэтому git-хук — не опция,
а обязательная часть комплекта: он не зависит от памяти модели и сработает всегда
при коммите чувствительных файлов.

## Настройка триггеров под свой проект
Открой `AGENTS.md` и `scripts/security-precommit.sh` — список "чувствительных"
ключевых слов (auth, payment, sql, upload, cors, ...) можно расширить под
специфику своего стека (например, добавить `graphql`, `jwt`, `s3` и т.п.).
